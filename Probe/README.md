# SelectEnglish 原生应用

此目录保留历史名称 Probe，目前是完整菜单栏应用，会在配置服务后自动调用外部 AI，并非离线探针。项目使用和数据说明见[根目录 README](../README.md)及[隐私说明](../PRIVACY.md)。

```sh
bash Probe/test.sh
bash Probe/build.sh
open .build/probe/SelectEnglish.app
```

开发构建为双架构临时签名包，不是公证发行版。授权、真实硬件交付和服务质量需分别验证。日常使用仅运行 `/Applications/SelectEnglish.app` 一个副本。

## 本机选区诊断

打开“译 → 触发与选区状态”，在 TextEdit 选中公开例句，选择目标应用后点击“读取指定应用选区”。它只通过辅助功能读取选区，不使用复制兼容、不调用 AI；浮层“重试”或已配置后的物理重按会调用服务。原始事件计数、stage 2、完整选区与 AI 成功是不同证据，不能相互替代。

`Probe/Experiments/` 是单独的历史被动事件实验，只输出数字元数据。当前不再提供历史“5 秒后读取”控件。

## 浏览器 PDF 候选方案

`fix/browser-pdf-selection` 分支提供默认关闭的浏览器复制兼容。重按或显式“翻译当前选区（PDF 推荐）”菜单 / `⌃⌥⌘T` 触发后，辅助功能读取失败才尝试复制。诊断窗口的“读取指定应用选区”仍只使用辅助功能，不复制、不调用 AI。

复制事务先完整备份剪贴板，在清空后向原浏览器进程定向发送 ⌘C，读取新文本，再在观察到的版本仍归本事务时尽力恢复。备份无法完成则不修改剪贴板。系统无法证明首个新写入的来源；并发复制可能造成无关文本被当作结果，恢复也不能保证完全。剪贴板管理器可能记录这些变化。

后续候选加入本机复制预览：必须核对并点击“分析选文”后才发送 AI；取消、关闭和未确认时不发送复制结果。直接从焦点元素读取成功的翻译入口仍可自动分析；从 PDF 子树取得的候选可能不完整，也必须预览确认。0.10.3/build16 未含此确认门槛，且实际 PDF 重按仍失败，不视为完成修复。新入口可避免重按正文先清除选区的问题，但原 PDF 实机读取与翻译仍需独立验证。详见 [PDF 选区说明](../docs/BROWSER-PDF.md)与[隐私说明](../PRIVACY.md)。
