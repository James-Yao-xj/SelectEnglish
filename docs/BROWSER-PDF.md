# 浏览器 PDF 选区

此页说明 `fix/browser-pdf-selection` 分支的候选修复；**0.10.3 / build 16 实测未解决目标 PDF 的重按取词**，后续改动仍需验证。已发布的 [v0.10.0-beta.1](https://github.com/James-Yao-xj/SelectEnglish/releases/tag/v0.10.0-beta.1) 安装包不包含这次修复；不要将候选代码的能力视为已发布版本的保证。

## 支持范围

目标是浏览器中**可选择文字**的 PDF。默认通过 macOS 辅助功能接口读取实际选区；仅能在画面上看到文字，不代表应用可以读取。

读取器先检查焦点元素的选中文字，再尝试该元素提供的选区范围或文本标记范围。如果焦点位于可确认的 PDF 容器内，会在这个 PDF 子树中有限查找选区。范围、长度、节点数、调用次数与时间均受限制，跳过工具栏及表单控件。子树中发现的候选可能只是选区片段，会显示“可能不完整”的预览，必须核对并点击“分析选文”后才分析；不会自动拼接碎片或把整页当作选文。无法取得有效选区时明确失败。

不读取整份文档，也不添加 OCR。扫描件、纯图片 PDF 仍不支持；复制受限文件不保证可用，也不会绕过其权限或 DRM。Safari 的 PDF 行为尚未完成本轮实测，Chrome 0.10.3 的物理重按已失败，后续候选结果需单独核对。

## 可选复制兼容

部分自定义网页 PDF 阅读器能选中文字，但不通过辅助功能暴露文本。本分支在设置中提供默认关闭的浏览器复制兼容；自行开启后，仅在重按或显式“翻译当前选区”菜单/快捷键触发、来源为受支持浏览器且辅助功能读取失败时，才尝试向重按时的原浏览器进程定向发送 ⌘C 复制选区并取得文本。快捷键通过 `CGEvent.postToPid` 指向原浏览器，不在系统范围发送，也不监听全局键盘。手动选区诊断不触发此功能。

复制前备份剪贴板全部可备份项目；无法完整备份则在修改前停止。随后临时清空剪贴板，触发浏览器复制，读取文本，并在剪贴板仍属于本次操作时尝试恢复。若用户或其他程序同时复制，应用尽力避免覆盖新内容，但不能保证完全恢复。系统无法确认写入者，复制命令后的首个新写入也可能来自其他程序，不能仅凭变化计数保证取得的是原选区。本分支加入本机预览与明确分析确认：复制结果在核对并点击“分析选文”前不发 AI；旧 0.10.3 没有此门槛。剪贴板管理器或同步工具可能保留这些变化；详细数据边界见[隐私说明](../PRIVACY.md)。

## 保留选区的触发方式

新分支增加“译 → 翻译当前选区（PDF 推荐）”与 `⌃⌥⌘T`（Control + Option + Command + T）。选中文字后使用此入口，可避免再次点击 PDF 正文可能清除选区的问题。菜单与快捷键也受复制兼容开关和复制预览确认约束；直接从焦点元素读到的选区仍可自动分析；PDF 子树候选须先核对可能不完整的预览。注册固定快捷键不等于监听键盘内容。这是待实测的候选方案，尚不属于上方已发布安装包。

## 如何验证

1. 统一运行候选版 `/Applications/SelectEnglish.app`，确认辅助功能授权、输入监听访问及监听启用正常。
2. 在浏览器打开公开、可选择文字的 PDF，先选中一句简短英文，避免选中地址栏、搜索框或批注输入框。
3. 从“译 → 触发与选区状态”选择该浏览器，使用“读取指定应用选区”，核对返回内容与选区完全一致。此按钮不自动调用 AI。
4. 再回到同一 PDF 重新选中文字，物理重按并松开，检查选区高亮是否仍在，再核对触发、完整读取及浮窗展示。直接从焦点元素读取成功且已配置时会自动分析；复制结果和 PDF 子树候选则需先核对并确认。测试只用公开例句。

手动读取通过不能替代物理重按验证；检测到重按也不等于成功读取选区。遇到失败时先用 TextEdit 对比权限，再记录应用版本、浏览器版本、公开 PDF 地址、是否能选中文字及脱敏错误提示。不要提供私人 PDF、密钥或完整私人选区。
