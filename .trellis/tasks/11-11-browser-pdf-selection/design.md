# Design
Read focused AXSelectedText first. Add compatible selection attribute/range extraction and bounded focused PDF viewer search only where supported. Fix process identity at trigger, stop on termination. Bounds on traversal, cycle checks, per-element timeouts/overall budget prevent serialAXqueuehang. No hidden/background tabs/windows or arbitraryselectedtext fromdifferentcontrols; selected ranges must be nonempty, valid and sourced from sameelement. Never fetch whole-document strings as fallback. Native source APIs to verify before implementation. Testadapter preserves productionalgorithm and permits failure/timeout/no-selection coverage without realpermissions.

## Autonomous selection-preserving trigger and confirmation (2026-11-17)
Keep Force Click as the primary trigger. Add explicit status-menu translation and exclusive public Carbon Control-Option-Command-T hotkey, without ordinary keyboard monitoring. Snapshot live external foreground PID/launch before activation; menu commands use the source captured when that menu opened and run after tracking closes. Fail visibly if source cannot be established or registration conflicts. Do not reactivate an old app or pre-copy/poll selections.
After a failed AX read, copy setup may take an additional bounded80ms to capture the focused AXWindow where supported; the direct AX path retains its own1.5s budget. Compare that same window during browser copy acquisition; a lost or changed captured window cancels acquisition. AXWindow does not identify browser tabs. Preserve process/generation and event-time dismissal guards.
Clipboard first-writer identity cannot be proven. Every copied-text result must show a preview and require the explicit 分析选文 action before any AI request or result reuse. The confirmed action sends the displayed snapshot and can proceed after foreground changes; cancellation/new capture/settings still invalidate it. Authoritative AX text can retain automatic analysis; manual diagnostics remain AX-only and offline.

## Scoped PDF result confirmation
The bounded PDF subtree search cannot prove a descendant candidate is the full selection. Every result outside the directly focused element carries requiresConfirmation=true. Display it as “PDF 辅助读取预览：可能不完整，请核对文字后点击‘分析选文’。” It must never enter automatic cache reuse or HTTP. Focused-element AX text/ranges/markers retain their existing automatic policy; clipboard previews retain their separate warning and confirmation. Do not join sibling fragments, expand traversal or claim complete PDF compatibility.

## Cooperative AX capture cancellation (build18)
Each capture creates one thread-safe SelectionCapturePermit shared by AX and any later browser copy. Controller invalidation cancels that permit before discarding references. SelectionReader checks it before process/focus AX setup, SelectionExtraction combines it with source liveness, and native AX preparation checks it before timeout setup and each attribute request. Recheck before copy-window setup and publication. Cancelled queued reads perform no AX operations; an already-issued AX operation is not forcibly interrupted and retains its existing per-call timeout (at most80ms). Preserve generation guards, original source checks and the direct1.5s budget.
Tests use the production extraction algorithm on one serial queue with an injected blocked fake attribute call. Cancel that active capture and four queued requests, then release the fake call: the active result is discarded with no later AX calls, queued requests issue zero calls, and the newest capture completes. No real AX/UI/clipboard/key access or timing-based latency promise.

## Credential replacement reported-failure boundary (build19)
For a nonempty new key from a validated configuration, KeyStore.saveBound clears ai.keyOrigin before calling the credential writer. Bind the new origin only after that writer returns successfully. A reported failure, before or after byte replacement and even on the same origin, leaves the credential unbound. Never restore an old binding without restoring its old bytes. Existing configuration validation rejects a missing binding before cache/credential/HTTP entry. Endpoint/model save follows successful replacement. This ordering is not an atomic file-plus-UserDefaults transaction and gives no crash or power-loss guarantee; do not add synchronization, migration or another storage format. Explicit deletion can leave an old binding after a reported failure, but a removed key reads nil and cannot start HTTP. Test with a unique defaults suite and injected fake writer only.
