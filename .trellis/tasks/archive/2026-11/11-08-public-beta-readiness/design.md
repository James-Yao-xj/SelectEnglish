# Design
Preserve bundle identity/internal executable, app data, capture generation guards, nonactivating paper result popup and response format. Public candidate0.10.0/build13; beta release label separate from CFBundle numeric version. Minimum13.0 is a build floor, not a tested hardware promise.
Build takes an explicit universal target and mode, produces canonical-named app under .build with isolated module caches; production package contains only app+bundled help/license/privacy data. Formal path preflights identity/notary profile, signs with hardened runtime/timestamp, submits and requires Accepted, staples+verifies, packages after stapling, verifies ZIP extraction and SHA. Beta path is explicitly adhoc/prerelease. Keep build.sh developer invocation compatible where possible.
Onboarding uses one AppKit window reachable from both menus. Initially show only for unconfigured first-time users, remember dismissal/seen independently of AI config. Live statuses reuse monitor and AX trust; explicit buttons reuse authorization actions and settings. Explain user endpoint transmission before setup. Do not prompt permissions automatically.
CI reads no repository secrets, checks both host architectures on documented GitHub runner labels. Release workflows avoid automatic public upload from untrusted PRs. External verification checklist records pending gates rather than placeholders marked passed.
