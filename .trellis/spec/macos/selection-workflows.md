# Selection and learning workflow contracts

## Selection-preserving commands and clipboard confirmation
1. **Scope / trigger:** PDF mouse-down can clear selection before Force Click. Keep Force Click; add `SelectionHotKey.start(action:)` for exclusive Control-Option-Command-T and the menu command. Register, handle, and clean up Carbon objects on the main thread; do not add a global keyboard monitor.
2. **Signatures:** `SelectionCommandIdentity.matches(pid:launchDate:)` binds a live process. `SelectionTextOrigin.analyzeAutomaticallyIfAllowed(requested:analyze:)` is the production routing boundary. `CapturedSelectionWindow.capture(pid:)` adds an optional bounded focused-window guard only after failed AX, outside the direct AX read budget.
3. **Contracts:** snapshot external process identity at hotkey delivery or menu opening, revalidate after menu closes, and never reactivate a stale source. Window equality cannot identify a tab. Only direct accessibility selection enters automatic analysis/cache lookup. Clipboard text is shown unchanged as a preview; an explicit Analyze action authorizes that immutable snapshot and may proceed after foreground changes. Keep generation cancellation before credential/HTTP/publish.
4. **Validation / errors:** occupied/unavailable hotkey reports failure and leaves the menu available. Unresolved source clears pending work and shows instructions. Failed/empty copy never analyzes. A missing AX window reference provides no window guard and must not be described as one. Clipboard first-writer attribution and restoration remain best effort.
5. **Cases:** Good: select a PDF sentence, press the registered chord without clicking the PDF, inspect any copy preview, then Analyze. Base: normal AX selection auto-analyzes. Bad: automatically send the first clipboard writer, reactivate an old browser, or claim tab identity from a window reference.
6. **Required tests:** production automatic action router blocks clipboard/cache/HTTP entry; explicit requests and manual diagnostics retain behavior. Test process/window mismatch and missing-reference semantics; native shortcut/menu capture uses a public fixture separately from fake tests. Do not post real keys or access the native clipboard in offline tests.
7. **Wrong vs correct:** do not run `analyze()` unconditionally after copy. Route by selection origin and show a distinct Analyze label. Do not claim a fake command event proves selection retention in Chrome.

## Deferred pressure handoff cancellation
1. **Scope / trigger:** a pressure event can wait on the main queue while a later mouse-down arrives. Preserve source event uptime rather than replacing it with callback delivery time.
2. **Signatures:** `ForceClickMonitor.onTrigger` passes `(NSRunningApplication, CGPoint, TimeInterval)`. `DeferredCaptureTriggerState.schedule(timestamp:)`, `observeMouseDown(timestamp:)`, `take(_:)`, and `cancel()` govern the queued handoff.
3. **Contracts:** observe mouse-down from existing passive/local/global monitors even when the panel is hidden. Later input cancels queued work; late delivery of the original initiating click does not. Explicit controller invalidation and listener stop cancel pending handoffs. After handoff, `PopupDismissalState` retains the original cutoff across capture/analysis transitions.
4. **Validation / errors:** superseded/cancelled/consumed tokens return no trigger. An older completion cannot clear a newer capture. Preserve all event masks and permission boundaries.
5. **Cases:** Good: trigger100, laterclick102, callback105 cancels. Base: initiatingclick99 delivered late remains harmless. Bad: callback105 becomes cutoff and ignores click102.
6. **Required tests:** delayed click before schedule, between schedule/take, after handoff, original click ordering, supersession, once-only consumption, explicit cancellation and stop integration.
7. **Wrong vs correct:** use the pressure event timestamp for `popup.beginCapture`, not `ProcessInfo.systemUptime` sampled during deferred delivery. Monotonic current uptime remains appropriate for measuring duration.

## Scoped PDF candidate completeness
1. **Scope / trigger:** a selected descendant may expose only one fragment of a multi-node PDF selection. The current bounded adapter cannot prove a complete unique result.
2. **Signatures:** `SelectionExtraction.Result.requiresConfirmation` and `SelectionReader.Result.requiresConfirmation` are false for focused-node direct/range/marker results and true for every scoped fallback, including a nonfocused aggregate ancestor.
3. **Contracts:** preserve exact candidate text and the existing traversal bounds. Route scoped results as `SelectionTextOrigin.scopedAccessibility`; label possible incompleteness and require explicit Analyze. Neither clipboard nor scoped origins may enter automatic AI/cache routing. No sibling concatenation or document-value harvesting.
4. **Validation / errors:** missing/budget-exhausted selections fail normally. A returned scoped candidate is never evidence that the complete selection was recovered, even when only one node was found. Fake tree topology is not evidence of actual Chrome topology.
5. **Cases:** Good: a two-sibling selection yields a clearly marked candidate preview, without automatic HTTP. Base: focused selected range stays automatic. Bad: first selected static-text node is sent as if it were the full sentence.
6. **Required tests:** focused direct/range/marker flags, scoped aggregate/leaf flag, multi-sibling and bounded-child candidates, production origin router blocks automatic analysis/cache/HTTP.
7. **Wrong vs correct:** do not infer completeness from the absence of a second result in a bounded search. Carry explicit uncertainty to the UI and require confirmation.

## Sentence vocabulary source forms
Live `Analysis.validated(source:)` checks every vocabulary word against a boundary-aware literal source span. Case and whitespace runs may differ; inflections, compound connectors, and technical punctuation must not. A sentence cannot accept unrelated vocabulary, substrings of larger words, or `C` as the original form of `C++`. Keep the isolated-word requirement, contextual meanings and approximate CET-6 judgment. Historical decoding never applies live validation. Required assertions cover unrelated mocked-HTTP vocabulary, original forms, sentence boundaries, compounds/technical terms, multiline phrases, and existing history compatibility. Validation errors must not echo source text or AI response bodies.

## Cooperative AX capture cancellation (build18)
Each capture creates one thread-safe SelectionCapturePermit shared by AX and any later browser copy. Controller invalidation cancels that permit before discarding references. SelectionReader checks it before process/focus AX setup, SelectionExtraction combines it with source liveness, and native AX preparation checks it before timeout setup and each attribute request. Recheck before copy-window setup and publication. Cancelled queued reads perform no AX operations; an already-issued AX operation is not forcibly interrupted and retains its existing per-call timeout (at most80ms). Preserve generation guards, original source checks and the direct1.5s budget.
Tests use the production extraction algorithm on one serial queue with an injected blocked fake attribute call. Cancel that active capture and four queued requests, then release the fake call: the active result is discarded with no later AX calls, queued requests issue zero calls, and the newest capture completes. No real AX/UI/clipboard/key access or timing-based latency promise.

## Credential replacement reported-failure boundary (build19)
For a nonempty new key from a validated configuration, KeyStore.saveBound clears ai.keyOrigin before calling the credential writer. Bind the new origin only after that writer returns successfully. A reported failure, before or after byte replacement and even on the same origin, leaves the credential unbound. Never restore an old binding without restoring its old bytes. Existing configuration validation rejects a missing binding before cache/credential/HTTP entry. Endpoint/model save follows successful replacement. This ordering is not an atomic file-plus-UserDefaults transaction and gives no crash or power-loss guarantee; do not add synchronization, migration or another storage format. Explicit deletion can leave an old binding after a reported failure, but a removed key reads nil and cannot start HTTP. Test with a unique defaults suite and injected fake writer only.

## Main-actor responsiveness and exact previews (build20)
BrowserCopySource.isForegroundProcess is lightweight process identity only. CapturedSelectionWindow.isCurrentOnWorker performs AX only on serial workers; isCurrentAsync awaits a dedicated serial worker. Copy transactions validate the window asynchronously before backup, again after backup and before clipboard clear, and before accepting fresh text. After each await, recheck cancellation/process/generation and clipboard version. Never yield between the final version comparison and clear, string read or restore. Shortcut posting still validates the window on its existing worker immediately before keydown and always sends keyup cleanup. Restore only the observed owned clipboard version, including cancellation paths. Return exact raw copied text, trim solely to detect empty content, and enforce the 20k limit against raw text. Missing AX trust prevents copy fallback entirely and shows the existing permission instructions; registered commands do not require an active pressure listener.

Window validation carries the shared capture permit and skips queued AX work if cancelled; check again after the issued IPC returns. Direct selection retains its1.5s read budget. Window capture and later identity validations are separate operations, each using an80ms AX messaging timeout per request; this is not an80ms total budget for the whole setup.
